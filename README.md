# AIrIA

> A personal AI that runs on your own hardware. Conversations stay on the device.

AIrIA is a pnpm/Turborepo monorepo containing a web app and a React Native client.
The mobile client runs inference **on-device** via [`llama.rn`](https://github.com/mybigday/llama.rn)
(llama.cpp bindings), with an optional Ollama endpoint for heavier models.

Its distinguishing piece is a **capability router**: each turn is classified as
`vision`, `code`, or `reason`, and the matching model is loaded to answer it.

## Getting started

**Prerequisites:** Node ≥ 18, pnpm 11, and — for the mobile app — Xcode (iOS) or
Android Studio with JDK 21 (Android).

```bash
pnpm install
```

The workspace uses `node-linker=hoisted` (see [`.npmrc`](.npmrc)). This is
required: Expo's autolinking cannot resolve native modules through pnpm's default
symlinked store.

### Web app

```bash
pnpm dev
```

### Mobile app

The mobile client needs a **dev-client build**, not Expo Go — on-device inference
depends on native modules Expo Go does not bundle.

```bash
pnpm --filter @airia/rn ios
```

```bash
pnpm --filter @airia/rn android
```

Android also needs `JAVA_HOME` and an `android/local.properties` pointing at your
SDK. Both native directories are generated by `expo prebuild`, so a clean rebuild
is `npx expo prebuild --platform ios --clean` from `packages/airia-rn`.

### Checks

```bash
pnpm test && pnpm typecheck
```

## How it works

### Capability routing

Every message runs through a two-stage router before inference
([`CapabilityRouter.ts`](packages/airia-service/src/CapabilityRouter.ts)):

1. **Rules pass** — attachments and hard signals decide immediately. An image or a
   visually-laid-out document (PDF, slides, spreadsheets) routes to `vision`; source
   files, fenced code, and stack traces route to `code`.
2. **Semantic pass** — for everything else, bag-of-words cosine similarity against
   per-capability exemplars, with a **0.62** threshold. Below that it defaults to
   `reason`, so an ambiguous question gets the general model rather than a guess.

The router then loads the matching on-device model, hot-swapping if it differs from
the one already resident.

### Models

| Capability | Model | Size | Min RAM |
|---|---|---|---|
| `reason` (default) | Gemma 3 1B (Q4) | 806 MB | 2 GB |
| `code` | Qwen 2.5 Coder 1.5B (Q4) | 1.1 GB | 3 GB |
| `vision` | Qwen 2.5 VL 3B (Q4) | 1.9 GB + 845 MB projector | 4 GB |
| `reason` (alt) | Llama 3.2 1B (Q4) | 770 MB | 2 GB |

Models download on demand from Hugging Face into app storage. Vision additionally
needs its **multimodal projector** (`mmproj`) — the weights alone cannot accept an
image — so it is fetched alongside the model and loaded via `initMultimodal`.

### Graceful degradation

A missing model never blocks a reply. If a turn routes to `vision` but that model
isn't downloaded, AIrIA answers with whatever is loaded **and says so**, offering a
one-tap download:

> Routed to **vision**, but Qwen 2.5 VL 3B (Q4) isn't downloaded — answered with
> Gemma 3 1B (Q4).

This matters more than it looks. A text-only model handed an image question will
answer confidently and entirely from imagination. Naming the substitution is what
separates a degraded answer from a fabricated one.

The same principle applies to documents: when text extraction fails, the prompt
states the contents could not be read rather than leaving the model to invent them.

### Risk-tiered skills

Skills declare a risk tier — `informational`, `consequential`, or `regulated` —
which sets grounding, output, and gating policy. Inheritance is **tighten-only**:
a skill may raise its own restrictions but never relax an inherited one, enforced
at validation time. Regulated domains (medical, legal, compliance) refuse to answer
without a grounded skill rather than falling back to the base model.

## Attachments

The `⊕` button accepts photos and documents. Images are normalised to a bounded
JPEG before inference — `stb_image`, which the vision model decodes with, cannot
read HEIC. Documents route by mime type and extension, and have their text pulled
into the prompt.

## Layout

| Package | Purpose |
|---|---|
| [`@airia/types`](packages/airia-types) | Shared types — messages, routing decisions, skill contracts |
| [`@airia/service`](packages/airia-service) | Capability router, tier router, context and memory |
| [`@airia/db`](packages/airia-db) | Persistence |
| [`@airia/ui`](packages/airia-ui) | Cross-platform components and theme tokens |
| [`@airia/fe`](packages/airia-fe) | Web app |
| [`@airia/rn`](packages/airia-rn) | React Native client, llama.rn bridge, model registry |

Business logic lives in `service`, `db`, and `types` with no DOM or React Native
dependencies, so web and mobile share it directly.

## Known gaps

- **Real-device GPU is unverified.** Multimodal init requests GPU only on physical
  hardware — the iOS Simulator's Metal shim aborts the process on CLIP tensor
  upload, as a native trap JavaScript cannot catch. The device path has not been
  exercised.
- **PDF text extraction is not implemented.** The pure-JS route (`unpdf`/pdf.js)
  is not viable under Hermes — it ships `import.meta`, which fails the release
  bundle outright, and its renderer additionally needs `DOMMatrix` and canvas.
  PDFs currently report that their contents could not be read, so the model
  declines rather than guessing. Getting them working needs either a native
  extractor or rendering pages to images for the vision model; the latter would
  also cover scanned PDFs, which text extraction never could.
